## 每次发版的步骤

1. **改版本号**：`src-tauri/tauri.conf.json` 的 `version`（三处之一；Workspace 继承它），
   提交并打 tag（如 `v3.0.1`）。
2. **打包**（PowerShell，在 `client2` 下）：

   ```powershell
   $env:TAURI_SIGNING_PRIVATE_KEY = "E:\OpenCode\diagramon\keys\diagramon.key"
   $env:TAURI_SIGNING_PRIVATE_KEY_PASSWORD = "<keys\password.txt 的内容>"
   npx tauri build --bundles nsis
   ```

   （npx 用的是 `E:\OpenCode\diagramon\.tooling\node_modules` 里装好的 tauri-cli 2.12.2）
   首次 release 编译约 28 分钟，之后增量构建几分钟。
   **口令别提交**；`keys/` 在两个仓库之外，不会误提交。

3. **产出三件套**（`target/release/bundle/nsis/`）：

   | 文件 | 用途 |
   |---|---|
   | `Diagramon_<版本>_x64-setup.exe` | 安装包（也是更新包） |
   | `…setup.exe.sig` | minisign 签名（更新器校验用） |
   | `latest.json` | 更新清单（本次构建已生成模板，**每次发版要重新生成**：改 version/notes/url，sig 用新的） |

4. **上传到更新源**（diagramon.agentctxsync.com）。两种部署方式二选一：

   **静态托管（推荐起步）**：把 endpoint 里的 `{{target}}/{{arch}}/{{current_version}}`
   去掉，改成固定 `https://diagramon.agentctxsync.com/latest.json`（改
   `tauri.conf.json` 后要发一版才生效）。然后上传：
   - `latest.json`（清单，里面 `platforms.windows-x86_64.url` 指向安装包的最终 URL）
   - `Diagramon_<版本>_x64-setup.exe` + `.sig`
   旧版本文件**不要删**（老客户端可能还在下载）。

   **动态服务**：保留 `{{current_version}}` 占位，服务端按客户端当前版本返回
   200（JSON 同 latest.json）或 204（已是最新）。`service/` 仓库加一个只读路由即可。

5. **升级链路自测**（每次发版前做一遍）：本机装上一个旧版本（如 3.0.0），把
   `latest.json` 的 `version` 改成新版本并上传，启动旧版 → 帮助 → 检查更新 →
   应提示新版本 → 下载安装 → 自动重启后 `关于` 里是新版本号。

## 仍未办的手续

- [ ] **正式域名备案**（现在的 agentctxsync.com 是临时的）
- [ ] **Windows 代码签名证书（Authenticode）**：没有它 SmartScreen 会拦安装包。
        有了证书后用 `signtool sign /fd sha256 /tr <时间戳> /td sha256 …`
        对 **setup.exe** 签名（在 tauri 打包**之后**、上传**之前**）；
        更新器的 minisign 签名与此无关，两者都要。
- [ ] macOS / Linux 产物（需要对应平台；本机只有 Windows）
- [ ] 自动更新服务端路由（若选"动态服务"方案）

## 已知边界

- 更新器只校验 **minisign** 签名（保证更新来自我们），不校验 Windows 证书 ——
  所以安装包本身的 SmartScreen 拦截仍需 Authenticode 解决。
- `pubkey` 换了 = 老客户端全部拒绝更新。**私钥与口令务必备份**（keys/README.txt 有说明）。
