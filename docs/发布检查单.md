## ⚠️ 曾经的致命缺口：安装包里没有画布引擎（2026-10-11 修复）

第一次打包出的安装包只有 7.32 MiB —— 因为 `bundle.resources` 是空的，
**98MB 的 drawio/Excalidraw/graphviz/mermaid 资产和 `ui/` 前端文件都没进安装包**。
本应用的 `dgm` 协议是**从磁盘 serve 文件**的（不是嵌入二进制），装出来的应用会白屏。

修复（已验证：7z 解包确认 2946 个 drawio 文件、mermaid.min.js、ui/index.html 都在）：

1. 打包前先跑 `node tools/fetch-assets.mjs` 把资产汇到 `assets/`（93.7MB，--verify 可校验）；
2. `tauri.conf.json` 的 `bundle.resources` 配了映射：`{"../ui/": "ui/", "../assets/": "assets/"}`；
3. 打包后**必做**：`"C://Program Files//7-Zip//7z.exe" l <安装包> | findstr "ui\index.html assets\drawio"`
   抽查两个关键路径在不在。

## 每次发版的步骤

1. **改版本号**：`src-tauri/tauri.conf.json` 的 `version`（三处之一；Workspace 继承它），
   提交并打 tag（如 `v3.0.1`）。
2. **打包**（PowerShell，在 `client2` 下）：

   ```powershell
   $env:TAURI_SIGNING_PRIVATE_KEY = "E:\OpenCode\diagramon\keys\diagramon.key"
   $env:TAURI_SIGNING_PRIVATE_KEY_PASSWORD = "<keys\password.txt 的内容>"
   npx tauri build --bundles nsis
   ```

   （npx 用的是 `E:\OpenCode\diagramon\.tooling\node_modules` 里装好的 tauri-cli 2.12.2）
   首次 release 编译约 28 分钟，之后增量构建几分钟。
   **口令别提交**；`keys/` 在两个仓库之外，不会误提交。

3. **产出三件套**（`target/release/bundle/nsis/`）：

   | 文件 | 用途 |
   |---|---|
   | `Diagramon_<版本>_x64-setup.exe` | 安装包（也是更新包） |
   | `…setup.exe.sig` | minisign 签名（更新器校验用） |
   | `latest.json` | 更新清单（本次构建已生成模板，**每次发版要重新生成**：改 version/notes/url，sig 用新的） |

4. **（可选，但公开发版建议带）便携版 ZIP**：

   ```bash
   node tools/pack-portable.mjs          # 版本号取自 tauri.conf.json
   ```

   产物 `target/release/bundle/portable/Diagramon-<版本>-win-x64.zip`
   （命名沿用旧仓库：`Diagramon-<版本>-win-x64.zip`，**文件在压缩包根**、无外层文件夹），
   作为**第 4 个附件**随三件套一起传。

   - 内容 = `diagramon.exe` + **`WebView2Loader.dll`** + `ui/` + `assets/` + `LICENSE` / `NOTICE`
     + `README-PORTABLE.txt`（中英对照的用法与依赖说明）。
   - **`WebView2Loader.dll` 不能漏**：release 的 exe 在导入表里是**动态**依赖它
     （`objdump -p target/release/diagramon.exe | grep "DLL Name"`），少了双击就起不来。
   - 布局必须让 **exe 同级**有 `ui/` 与 `assets/`：`src-tauri::ui_dir()` 先找 exe 同级的 `ui/`，
     `crates/assets::AssetRoots::detect()` 再看 `ui/../assets`（随包优先于源工作树）。
   - ⚠️ **打包前先删 `ui/.shots/`**：那是真机自检与探针的产物（约 4.8MB，`.gitignore` 里就有它），
     不属于产品内容。`pack-portable.mjs` 会过滤掉它，但**安装包那边过滤不了** ——
     `bundle.resources` 是按目录整体映射的，所以必须在**打包前**把这个目录清掉
     （`rm -rf ui/.shots`），否则安装包也会带上这 65 个开发文件。
   - 验证（两条都要做）：
     1. `7z l <zip>` 抽查 `diagramon.exe` / `WebView2Loader.dll` / `ui\index.html` / `assets\drawio`；
     2. **解压后实跑一次**：`./diagramon.exe` 看 stderr 首行
        `diagramon|roots|ui=…|source=…|packaged=…` —— `ui` 与 `packaged` 必须指向**解压出来的目录**，
        这是"便携布局成立"最直接的证据（本机实测：`ui=…\portable-test\ui`、
        `packaged=Some("…\portable-test\ui\../assets")`，随后 `boot:1-i18n → boot:3-load → hb:1` 说明前端真的起来了）。
   - 便携版**不参与更新链**：`latest.json` 仍指安装包；便携版的「检查更新」会下 NSIS 安装包，
     不会就地替换便携目录（发布说明里已写明）。

5. **发布到更新源（GitHub 主源）**——在 GitHub 建一个 Release（tag=版本号），
      附件传三件套：`Diagramon_<版本>_x64-setup.exe` + `.sig` + `latest.json`
      （`latest.json` 里 `platforms.windows-x86_64.url` 指向本 Release 的安装包附件 URL，
      signature 必须是 `.sig` 的**内容**——已自动化，见下）。
      `releases/latest/download/latest.json` 只认**已发布**（非草稿/非预发布）的最新 Release。

   全流程已可脚本化（PAT 走 socks5 代理，参考本次执行）：
   1) `git tag v<版本> && git push origin v<版本>`；
   2) `POST /repos/westsource/diagramon/releases`（tag_name/name/body）拿 release id；
   3) `POST https://uploads.github.com/repos/westsource/diagramon/releases/<id>/assets?name=<文件名>`
      逐个传三件套（Content-Type: octet-stream / json）；
   4) 草稿核对无误后 `PATCH /releases/<id>` `{"draft": false}` 正式发布。

   备源（`www.diagramon.com` / `agentctxsync.com`）：把**同一个更新清单 `latest.json`**
   放到 `{{target}}/{{arch}}/{{current_version}}` 这个路径上即可（动态路由或静态目录都行）。

   ⚠️ **占位符展开的真实取值（2026-10-12 读 `tauri-plugin-updater 2.13.3` 源码核实）**：
   - `{{target}}` = **只有操作系统**：`windows` / `darwin` / `linux`（`updater_os()`），
     **不是** `windows-x86_64`；
   - `{{arch}}` = `x86_64` / `aarch64` / `i686`（`updater_arch()`）；
   - `{{current_version}}` = 当前应用版本，本机是 `3.0.0`。
   ⇒ Windows x64 上第 2、3 项会请求 **`/windows/x86_64/3.0.0`**（源文件注释里的例子
   也是这个形态：`…/update/darwin/aarch64/1.0.0`）。
   **别写成 `/windows-x86_64/…`** —— 那是清单 JSON 里**平台键**的写法，两处拼法不同：
   - URL 路径段：`windows` / `x86_64`
   - JSON 平台键：`windows-x86_64`（插件查找顺序是 `{os}-{arch}-nsis` → `{os}-{arch}`，
     我们的清单用两段式 `windows-x86_64`，命中第二个候选）
   **2026-10-12 实测：两枚备源都还没放** —— `www.diagramon.com` 无 DNS 记录（连不上），
   `diagramon.agentctxsync.com` 上 `/windows/x86_64/3.0.0` 返回 **404**（站点与 `/v1/*` API 是活的）。

   **当前发布状态（2026-10-12 更新，别再照着旧的"改草稿即可"做）**：
   v3.0.0 已**正式发布**——GitHub Release id `410183834`（tag `v3.0.0` → `a807234`），
   三件套已传并 `PATCH {"draft":false}`；Gitee Release id `1199158`（正文只放 GitHub 下载链接）。
   旧文档里那个"v3.0.0 草稿 Release（id 409339645）已传好待发布"**早已不存在**，别去找它。
   **每次发版都走**：改版本号 → `latest.json` **重新生成**（新 `.sig` 内容 + 当日 pub_date，
   它是 `target/` 下的产物、不入库，最容易拿旧的上去）→ `git tag -f` → `POST /releases`（先 draft）
   → 传三件套 → `PATCH {"draft":false}` → 发完**必须**用
   `curl -sL …/releases/latest/download/latest.json` 核对 `signature` 与本地 `.sig` 逐字节一致。

6. **升级链路自测**（每次发版前做一遍）：本机装上一个旧版本（如 3.0.0），把
   `latest.json` 的 `version` 改成新版本并上传，启动旧版 → 帮助 → 检查更新 →
   应提示新版本 → 下载安装 → 自动重启后 `关于` 里是新版本号。

        2. **Certum 开源开发者证书**：约 €25/年，面向开源项目，云签（SimpleSign）。
        3. **SSL.com / Sectigo / DigiCert OV**：$100-400/年，2023-06 起一律绑定硬件/云 HSM。
        注意：**OV 证书的 SmartScreen 信誉要靠下载量积累**，EV 才立竿见影。

        ```
        signtool sign /fd SHA256 /td SHA256 /tr <RFC3161 时间戳 URL> ^
          /f <证书.pfx> /p <PFX 口令>  target\release\bundle\nsis\Diagramon_<版本>_x64-setup.exe
        ```
        （Azure Trusted Signing 则用其 SDK：`signtool sign /dlib … /dmdf …`，无需 PFX。）
