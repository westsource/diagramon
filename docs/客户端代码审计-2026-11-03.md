## 1. 高危（逐条）

### H-1 SVG 消毒器可被 URL 内嵌 TAB 绕过 —— 打开恶意 `.dot`，点一下节点即拿到外壳页 JS 执行

**位置**：`ui/js/preview.js:1023`（`sanitizeSvgNode`，1010–1031），落点 `mountSvg:1034-1046`。

```js
} else if ((name === "href" || name === "xlink:href" || name === "src") && /^\s*javascript:/i.test(attr.value)) {
  n.removeAttribute(attr.name);
}
```

**问题**：WHATWG URL 解析会把 URL **任意位置**的 `\t` `\n` `\r` 删掉再判 scheme，而这个正则只容忍**前导**空白（`^\s*`）。

**端到端实证**（真 Chromium 155 + 仓库自带的 `ui/vendor/graphviz.js` 16.1.0 + 逐字复制的 `sanitizeSvgNode`）：

1. 恶意 DOT 源：
   ```dot
   digraph G {
     a [label="click me", URL="jav<TAB>ascript:void(fetch('/HIT-FROM-DOT'))"];
   }
   ```
2. `Graphviz.layout(dot, "svg", "dot", {})` 原样透传（graphviz 把 TAB 编成属性值里的真 TAB）：
   ```
   <a xlink:href="jav	ascript:void(fetch(&#39;/HIT-FROM-DOT&#39;))" xlink:title="click me">
   ```
3. 过 `sanitizeSvgNode` 后**属性存活**，浏览器解析出的协议是 `javascript:`：
   ```json
   { "xlink": "jav\tascript:void(fetch('/HIT-FROM-DOT'))", "resolved_protocol": "javascript:" }
   ```
4. 按 `mountSvg` 的方式挂进活 DOM，可信点击 → **审计用的本地服务端收到 `/HIT-FROM-DOT`**。

对照组（同样的图但 `URL="javascript:…"` 不带 TAB）被消毒器正确拔掉（`xlink:href` → `null`），
说明漏洞精确落在正则的锚定上，不是整体失效。

补充：`new URL("jav\tascript:x").protocol`、`"java\nscript:"`、`"java\rscript:"` 三种形态实测都返回 `javascript:`；
且 `%2e%2e`/裸 `..` 两种写法都能过，故不依赖浏览器是否做百分号归一。

**影响**：外壳页 `ui/index.html` 持有 `window.__TAURI__` 与全部 **77 条** IPC 命令（清单见 §6）。
一次点击 ⇒ 任意文件读（H-5）、任意 `.json` 删改（H-4）、任意路径写（M-3）、
覆盖 `settings.json` 把 AI/云网关改到攻击者主机从而**用 DPAPI 解出的真密钥主动送上门**（M-2/M-4）。
触发物是本应用明确列为不可信输入的第三方图表文件。

**修法**：判前先剥控制字符，并改成协议白名单而不是黑名单：
```js
const v = attr.value.replace(/[\u0000-\u0020]/g, "");
let proto = "";
try { proto = new URL(v, document.baseURI).protocol; } catch { proto = ""; }
const OK = new Set(["http:", "https:", "mailto:", "tel:", "data:"]);
if (proto && !OK.has(proto)) n.removeAttribute(attr.name);   // data: 还要再按 MIME 收窄，见 H-2
```
（`#` 片段引用 `protocol` 会等于文档协议，需单独放行。）

### H-2 属性静态扫描天然拦不住 SMIL：`<set>/<animate>` 在挂载后把 `href` 改成 `javascript:`

**位置**：`ui/js/preview.js:1016`（元素移除清单只有 `script, iframe, object, embed, link, base`）、`1018-1026`（只扫 `on*` / `href` / `xlink:href` / `src`）。

**实证**：三种形态挂载后 `getAttribute("href")` 全部为 `null`（SMIL 改的是**动画值**，不写回属性），
但可信点击后服务端三条全收到：
```
=== SMIL server-side hits: ["/HIT-XLINK-SMIL","/HIT-HREF-SMIL","/HIT-ANIMATE"] ===
```
```xml
<a><set attributeName="xlink:href" to="javascript:…" begin="0s"/><text>…</text></a>
<a><set attributeName="href"       to="javascript:…" begin="0s"/><text>…</text></a>
<a><animate attributeName="href" from="#z" to="javascript:…" dur="0.01s" fill="freeze" begin="0s"/><text>…</text></a>
```

**这条比 H-1 更根本**：任何"扫描属性值"的消毒器都拦不住动画，因为要拦的是**运行期状态**。
图表渲染完全不需要 SMIL，直接整类移除即可。

**修法**：`root.querySelectorAll("script, iframe, object, embed, link, base, animate, set, animateTransform, animateMotion").forEach(n => n.remove())`。

**同一条清单还漏的两项**（同一处修）：
- **`<style>` 不删**：SVG 内 `<style>` 挂进外壳页后作用于**整个文档**（CSS 不隔离），可整页重排做 UI 欺骗或用 `url()` 外带。mermaid/D2 合法产出 `<style>`，不能一删了之 —— 至少要过滤 `url(` 与属性选择器。
- **`<image>`/`<use>` 的 http(s) 外链不拦**：`<image href="https://evil/t.png">`（DOT 的 `image=` 可产出）挂载即发请求 ⇒ 打开文件即被追踪。协议白名单（H-1 的修法）顺带解决。

### H-3 `dgm://` 路径穿越：F-1 的三道防线漏掉 Windows「盘符相对路径」

**位置**：`crates/assets/src/lib.rs:149-156`。

```rust
// 注释声称：`is_absolute` 挡 `C:/x`；`has_root` 再挡 Windows 上 `/x` 这种形态
if rel_path.is_absolute() || rel_path.has_root() {
    return None;
}
let candidate = dir.join(rel_path);
candidate.is_file().then_some(candidate)
```

**问题**：`C:foo`（盘符后**无**分隔符）在 Windows 上是**盘符相对路径**，`is_absolute()` 与 `has_root()` **都是 false**，
但 `PathBuf::push` 遇到 prefix 组件就**整体替换**基目录。三道防线全部漏过，且不含 `\`、不含 `..` 段。

**实证**（仓库外临时 crate，用 `#[path]` 引入真实 `crates/assets/src/lib.rs`）：

```
url=http://dgm.localhost/C:%2e%2e/SECRET.txt
  uri.path()="/C:%2e%2e/SECRET.txt"
  resolve=> Some("C:../SECRET.txt")
  canon="\\?\C:\...\dgm-audit-probe\SECRET.txt"   bytes="top secret"   INSIDE_ROOT=false

url=http://dgm.localhost/C:../SECRET.txt          ← 已归一形态，同样逃逸
url=http://dgm.localhost/drawio/C:%2e%2e/SECRET.txt ← 经挂载点，同样逃逸
```
`..` 段检查之所以失效：`decoded.split('/')` 得到的段是 `C:..`，**不等于** `..`。
两种写法都能过，因此不依赖 WebView2 是否做 URL 归一。

被拒的形态（修复有效的部分，已复核）：`/drawio/..%5Csecret%5Cwin.ini` → `None`、`/drawio/../../SECRET.txt` → `None`、`/drawio/C:/Windows/win.ini` → `None`。

**可达范围**：`C:` 之后的相对路径按**该盘的进程当前目录**解析，可上跳一级后任意下降。
CWD 不完全由我们控制：双击 `.mmd` 启动时 Explorer 把 CWD 设为文档所在目录 [INFERENCE]；
便携/开发形态下 CWD 常是解压目录或仓库根。因此这是"受 CWD 锚定的越界读"，比 F-1 原本的无界 `..` 链窄，但仍是**守卫被绕过 + 实证读到根外文件**。

**修法**：与 `workspace::resolve_in_root` 对齐（那边已验证正确拒绝 `C:evil.mmd`）：
```rust
use std::path::Component;
if matches!(rel_path.components().next(), Some(Component::Prefix(_)) | Some(Component::RootDir)) {
    return None;
}
```
并补最后一道**结果侧**收口（顺带堵 junction/symlink）：`canonicalize` 后必须 `starts_with(dir.canonicalize())`。
补回归测试：`resolve(&r, "/C:x")`、`"/C:%2e%2e/x"`、`"/drawio/C:../x"` 均为 `None`。

### H-4 `conversation_read` / `conversation_delete` 的 `key` 未净化 ⇒ 任意 `.json` 删除与破坏

**位置**：`src-tauri/src/commands.rs:1322-1333`；`crates/app-core/src/conversations.rs:68-74`（`file_for`）、`125-137`（`load`）、`238-243`（`clear`）。

```rust
pub fn conversation_read(state: …, key: String) -> R<Conversation> {
    Ok(app_core::conversations::load(&state.paths.conversations_dir(), &key))   // key 原样
}
pub fn file_for(dir: &Path, key: &str) -> PathBuf { dir.join(format!("{key}.json")) }
```

`draft_key()` 有白名单（注释写着"白名单顺带防路径穿越"），但 `file_for` 这条**外部入口**没走它。

**两条独立的破坏面**：
1. `clear` 对 `file_for` 与 `meta_file_for` 各调一次 `remove_file` ⇒ `conversation_delete("C:/Users/<u>/AppData/Roaming/Diagramon/settings")` **删掉全部应用设置**；也可指向 UNC。
2. `load` 在 JSON 解析失败时执行 `fs::rename(&path, path.with_extension("json.bak"))` ⇒ 对**任何不是 `Conversation` 形状的 `.json`** 调一次 `conversation_read` 就把它静默改名（VS Code `settings.json`、项目 `package.json`/`tsconfig.json`/`tauri.conf.json`…）。

`Path::join` 遇绝对路径整体替换基目录 —— 与 H-3 是同一类错误，只是换了一个模块（那边专门堵过，这边没堵）。

**修法**：在 `file_for`/`meta_file_for` **内部**收口 —— 键必须匹配 `^[0-9a-f]{16}$` 或 `^draft-[A-Za-z0-9_-]+$`（复用 `draft_key` 的白名单），否则报错；`load` 的 `.bak` 改名只允许作用于 `dir` 的直接子项。

### H-5 `doc_open_paths` / `file_read_text`：任意文本文件全文读回前端

**位置**：`commands.rs:122-138`（`doc_open_paths`）、`315-323`（`file_read_text`）；`crates/app-core/src/document.rs:13-19`、`context_file.rs:14-38`。

```rust
pub fn from_path(id: String, path: &Path) -> std::io::Result<Doc> {
    let body = std::fs::read_to_string(path)?;   // 无扩展名校验、无大小上限
```
```rust
/// **不受"限制在工作区内"约束** —— …读用户自己指名的参考文件不该被它拦住。
pub fn file_read_text(path: String) -> R<AiContextFile> { … }   // context_file.rs 头注释：「不做扩展名白名单」
```

**问题**：CLI 入口 `open_cli_files` 走 `diagram_files()` 按注册扩展名过滤（正是上一轮 F-5 的修复），
**IPC 入口一条都没过滤** —— 与 F-5 完全同一类不一致，只是漏在另一条入口上。
`doc_open_paths` 返回的 `SessionPayload.docs[].body` 是**全文**，`read_to_string` 也没有 `context_file` 那样的 256 KiB 上限。
"用户自己指名"这个前提只在 UI 层成立；命令本身对任何同源页面开放（`build.rs` 未定义任何 app 权限）。

**影响**：`doc_open_paths(["C:/Users/<u>/.ssh/id_rsa"])`、`file_read_text("…/.aws/credentials")` 一次调用返回全文；
配合 H-6（承载页零 CSP）可直接外传。顺带把攻击者路径写进 `recent` 持久化。超大文件则整份进内存 ⇒ OOM（见 M-40）。

**修法**：`doc_open_paths` 复用 `diagram_files()`/`is_open_ext`；`from_path` 与 `context_file::read` 都改成
`File::open` → `metadata()` 拒掉目录/非普通文件 → `.take(MAX_BYTES + 1)` 限量读（同时让 `truncated` 如实算出）。
`file_read_text` 最好改成"后端开对话框、后端读"，前端不再传 `path`。

### H-6 承载页与 overlay 零 CSP，却与外壳同源并握有全部命令；wry 在 Windows 上把 `__TAURI__` 注入**所有帧**

**位置**：`src-tauri/tauri.conf.json:9-13`（`"csp": null`、`"withGlobalTauri": true`）；`src-tauri/src/lib.rs:141-160`（协议处理器只下发 `CONTENT_TYPE` 与 `CACHE_CONTROL`）；`ui/index.html:8-18`（唯一的 CSP，是 `<meta>`）。

F-2b 的修复只做在外壳页的 `<meta>` 上：`grep -i Content-Security-Policy` 全仓只命中 `ui/index.html`，
`ui/capture.html`、`assets/drawio/host.html`、`assets/drawio/index.html`、`assets/excalidraw/index.html` **全部没有**。
`tauri.conf.json` 的 `csp` 仍是 `null`，协议处理器也不补响应头。

**这一段是本轮的关键实证**：`ui/index.html:11-12` 的注释断言"承载页与外壳同源、同样摸得到 `__TAURI__`"。
Tauri 2.12.2 把所有初始化脚本包在 `main_frame_script { for_main_frame_only: true }` 里（`manager/webview.rs:161-166`），
乍看像是只注入主帧；但 **wry 0.57.0 明确写了这条在 Windows 上不成立**：

> `wry-0.57.0/src/lib.rs:1029` — **Windows:** scripts are always added to subframes regardless of the `for_main_frame_only` option.

Windows 走 `AddScriptToExecuteOnDocumentCreated`（`webview2/mod.rs:1373-1377`），注入所有帧。
Windows 是唯一出货平台 ⇒ **渲染不可信 `.drawio`/`.excalidraw`/SVG 的 iframe realm 确实持有 `window.__TAURI__` 与全部 77 条命令**，
且自身没有任何 CSP 阻止外传。`capabilities/default.json` 又把 `vision-overlay` 与 `main` 并列授权。

**修法**（性价比最高的一条）：把 `tauri.conf.json` 的 `app.security.csp` 设成与 `index.html` 那条等价的策略 ——
Tauri 会给**每个同源响应**注入并自动补 nonce/hash，承载页与 `capture.html` 一并覆盖；同时删掉 `index.html` 里重复的 `<meta>` 以免两处漂移。
若第三方引擎需要额外放行，只对那几张承载页单列更严的 `script-src`，别整站放开。
根治方案（承载页挪到第二个 origin）见 §7。

### H-7 `workspace_open` 自己就是守卫的根，且根规范化为空时 `inside()` 对所有路径恒真

**位置**：`src-tauri/src/workspace_cmds.rs:29-47`（`workspace_open` 唯一检查是 `is_dir()`）、`79-168`（new_file/rename/delete 全靠 `inside`）；`crates/app-core/src/workspace.rs:363-386`。

```rust
fn norm(p: &Path) -> Vec<String> { for c in p.components() { match c { … Component::CurDir => {} … } } }
let r = norm(root); let t = norm(target);
t.len() >= r.len() && r.iter().zip(t.iter()).all(|(a, b)| a == b)
```

`root = "."` ⇒ `r == []` ⇒ `t.len() >= 0` 恒真、空 `zip` 的 `.all()` 恒真 ⇒ **任何路径都"在工作区内"**。

**问题**：`workspace_new_file/rename/delete`、`check_writable`、`restrict_to_workspace` 全部建立在这个 `inside` 上，
而根由前端一句 `workspace_open(".")`（或 `workspace_open("C:\\")`）就能设定 —— 命令层不校验。
于是 `restrict_to_workspace` 即使打开也形同虚设。另外 `inside`/`resolve_in_root` 都是**纯词法**比较，
工作区里一个指向外部的 junction/symlink 即可绕过（`scan`/`search` 用 `follow_links(false)`，写删路径没有对应检查）。

**修法**：① `workspace_open` 拒绝相对路径与盘符根/UNC 根，要求 `canonicalize()` 成功且 `norm(root).len() >= 2`；
② `inside()` 在 `r.is_empty()` 时直接返回 `false`；③ 写/删/改名前对目标做 `symlink_metadata`，是 reparse point 就拒绝。

### H-8 DOT 递归无深度上限：16 KB 文件栈溢出，release 下进程直接终止

**位置**：`crates/app-core/src/convert_dot.rs:823-836`（`parse_stmt_list`）↔ `960-996`（`parse_subgraph`）互相递归；`610-625`（`emit_container`）自递归。三处都无深度计数。

**实测**（子代理，仓库外临时 crate）：
```
digraph G { subgraph s0 { subgraph s1 { … a -> b … } } }
  n=300  ok  输出 364 KB
  n=600  ok  输出 1.45 MB
  n=900  thread 'main' has overflowed its stack   ← 源仅 16 KB
  n=2000 / 20000 同样溢出
```

**影响**：机器生成的 `.dot`（按目录树、按调用链导出）就能杀掉整个 Tauri 进程。
`[profile.release] panic = "abort"`，栈溢出在 Windows 上是 `STATUS_STACK_OVERFLOW`，**不可捕获不可恢复**，未保存内容全丢。
`convert_text` 是同步命令、跑在 IPC 线程上，其栈通常小于主线程 8 MiB，真实阈值只会更低 [INFERENCE]。

同类：`convert.rs:1468-1492`（`emit_cluster`）、`2061-2085`（`D2Emit::emit_container`）在 ~20000 层时溢出（M-级，见 §2）。

**修法**：`parse_stmt_list` 加 `depth: usize`，超上限（如 256）返回 `Err(format!("第 {line} 行：subgraph 嵌套超过 {N} 层"))`；
`emit_container`/`emit_cluster` 改显式栈或加同一常量。一处定义、三条路径共用。

### H-9 全库搜索：小写化后的字节下标用回原串切片 ⇒ panic ⇒ release 下整进程终止

**位置**：`crates/app-core/src/workspace.rs:190-200`（`Matcher::find` 的 `Literal { ci: true }` 分支）。

```rust
let idx = if *ci { line.to_lowercase().find(needle)? } else { line.find(needle.as_str())? };
// 注释：小写化可能改变字节长度（极少数语言），取"到该字节为止的字符数"仍是对齐的  ← 这句是错的
Some(line[..idx.min(line.len())].chars().count())
```

`idx` 是**小写化后**串的字节下标，却拿去切**原串**。`to_lowercase` 会改变字节长度（`İ` U+0130 是 2 字节，小写成 `i̇` 是 3 字节），
偏移后可落在多字节字符中间。

**实测复现**（逐行同款代码，`needle = "目标"`）：
```
"İİ目标"  → panicked: end byte index 6 is not a char boundary; it is inside '目' (bytes 4..7)
"İ目标"   → panicked: end byte index 3 …
"ẞ目标"   → panicked: end byte index 2 … inside 'ẞ'
"aİ目标"  → panicked: end byte index 4 …
"İİİ目标" → 不 panic，但返回 Some(4)，真实字符下标是 3 ⇒ 列号系统性错位
```

**可达性**：`SearchRequest.case_sensitive` 默认 `false`（`app-ipc/src/lib.rs:938`）⇒ **默认路径**。
被搜索的文件是不可信输入（用户打开的第三方工作区/仓库）。
执行上下文：`search_run` 走 `tauri::async_runtime::spawn_blocking`，`search_once` 同步跑在命令线程 —— 两者在 `panic = "abort"` 下都终止整个进程。

**修法**：不要在变换后的串上取下标。改用 `regex::RegexBuilder::new(&regex::escape(query)).case_insensitive(true)`
（`find` 返回的就是**原串**字节区间，天然对齐，还顺带消灭每行一次的 `to_lowercase` 分配）；
或自建 `char_indices` 对齐的小写映射。同时给这条补一个 `İ` 回归测试。

### H-10 / H-11 / H-12 配色与 DOT→D2 会静默改坏用户文档

这三条是**数据损坏**类，且都落在"点一次按钮就落盘"的主路径上。

**H-10 `apply_d2` 丢容器路径、不过 `d2_id`**（`palette.rs:1738-1753`，配 `d2_nodes` 的 `touch`，`1497-1520`）
```rust
for id in ids { block.push_str(&format!("{id}.style.fill: \"{fill}\"\n")); }
for (from, to) in &scan.edges { block.push_str(&format!("({from} -> {to}).style.stroke: \"{line}\"\n")); }
```
`id` 是 `trim_matches('"')` 后的**裸名**，`D2Node.group`（容器名）记录了却从未使用。
违反本仓库自己写下的两条不变量：`convert.rs:2007` 与 `convert_dot.rs:581` 的 `path_of` 注释都说
"容器里的节点要写点号路径，否则顶层那行会造出一个同名新节点"；`d2syntax::d2_id` 的存在理由就是"带空格/点号/保留字的 id 必须加引号"。
实测（子代理）：
```
源: 集成层: { 网关 -> 数据库: SELECT }   写回: 网关.style.fill: … / (网关 -> 数据库).style.stroke: …  ← 全在顶层
源: "my node" -> b                       写回: my node.style.fill: …      ← 未加引号，D2 语法错
源: 节点#1 -> b                          写回: 节点#1.style.fill: …       ← `#` 起注释，样式丢失 + 多出裸节点
源: a; b -> c                            写回: (a; b -> c).style.stroke: … ← 括号内含 `;`，语法错
```
⇒ 对**任何使用容器的 D2 文档**点一次「自动配色」：真正的节点一个都没上色，同时在顶层凭空造出全套同名重复节点与重复边；`changed=true` 会落盘。
**修法**：`D2Node` 增 `path: String`（扫描时用 `groups` 栈拼 `容器.子容器.名`，每段过 `d2_id`），`apply_d2` 与边样式一律用该 path。等价于把 `convert_dot::Graph::path_of` 搬过来复用。

**H-11 `d2_nodes` 不认块字符串 `|md … |`**（`palette.rs:1520-1560`）
逐行扫描只识别 `#` 注释、`}`、`以 { 结尾`、`左: 右`。`formatter.rs:368 opens_block_string` **已经实现了同一件事**，
但 `palette` / `lint` / `outline` 都没用 —— 正是 `d2syntax.rs:1-9` 那段"为什么不各写一份"警告的漂移。
实测：`x: |md` 块里的 `正文里有个 { 花括号`、`还有 a -> b`、`|` 全被当节点写回，产出非法 D2 ⇒ 整份文档编译失败；`outline` 同时把散文列为节点。
**修法**：把 `opens_block_string` 提到 `d2syntax`，`d2_nodes`/`lint::d2`/`outline::d2` 三处共用块内跳过状态。

**H-12 `dot_to_d2` 静默丢孤立节点**（`convert_dot.rs:592-608`）
`emit_node` 四项（label / named shape / styles / dash）全空时**一行都不写**。
对照 `convert.rs:2055-2059` 的 `D2Emit::emit_node`，那里有明确兜底并写着注释：
> `// 上面四项都空时一行都没写，但节点本体仍要声明 …… 否则孤立节点会整段消失（B3：D2 导出静默丢节点）。`

**B3 的修复只落在 Mermaid 侧，DOT 侧漏了**。实测 `digraph G { lonely }` → 转出物为**空串**；`digraph G { a; b -> c }` → `b -> c`（`a` 丢了）。
`ShapeMap::Default`（`box`/`rect`）不写 shape 行，所以连 `node [shape=box]` 也救不回来。直接违反本模块"`notes` 里逐条写明丢了什么，不静默丢"的公开契约。
**修法**：照抄 `wrote` 标志，四项都没写时补一行 `{pad}{}`（裸 id 即 D2 声明）。

## 7. 做得好的（本轮确认的设计优点）

- **AI 工具面收得极紧**：`ai_tools::build` 四个工具全部只读内存文档模型，无 fs/shell/网络，也没有"模型直接改文档"的写口（`apply_patch` 被明确去掉并写明理由）。模型输出到文件系统之间隔着一个人类决定 —— 这是提示注入的正确答法。
- **`Finish` 五态把"钱的正确性"当一等公民**：`Interrupted`（思考已计费）明确排除自动重试；`with_max_tokens_ceiling` 只在"读到任何增量之前"的 400 上生效、同值不重发。无重试风暴路径。
- **密钥分层做对了**：DPAPI 落盘 + 文件名 `sha256(key)`（不泄键名、天然防穿越）+ `has_key`/`key_hint` 现算（不信磁盘旧值）+ 云令牌从不进任何命令返回值 + "已保存供应商只信 settings 里的地址"。缺的只是 M-4 那一环（settings 本身可写）。六个 `unsafe` 块逐一裁定为 sound（`LocalFree` 顺序正确、`DATA_BLOB` 布局一致、无别名/未初始化问题）。
- **`Conversion { body, notes }` 而不是裸字符串**：每一处有损退化都就地写进 `notes`。H-12/M-19/L-33 之所以能一眼认出是 bug，正因为这个契约把"允许静默"的空间压到了零。
- **`d2_id`/`d2_str`/`dot_id` 的"一律加引号"策略**：不枚举哪些字符危险，而是白名单式判定能否裸写 ⇒ 转换侧没有 id 折叠/注入问题（H-10 是调用方忘了用它，不是它本身不够严）。
