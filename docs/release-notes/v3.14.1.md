### 本次亮点

- **未保存草稿恢复回归**：新建、AI/转换产物等没有本地路径的草稿，改动后会写进应用数据目录的草稿仓；关闭软件再打开会恢复。它**不受“自动保存”开关影响**。
- **已保存文件不再被草稿机制影响**：有本地路径的图形文件只在「设置 → 编辑器 → 自动保存（写回原文件）」开启时才写回原文件；关闭时改动只留内存。已保存文件**永不进草稿仓**，重启不会多出未命名副本。
- **退出语义明确**：有草稿时，退出对话框提供「退出并保留草稿」与「退出并丢弃草稿」；正常退出前会同步写一次草稿，避免恢复出旧版本。
- **AI / 转换产物只进内存**：AI「应用到编辑器」、AI 增强产物、格式转换产物都受 `hold` 保护，自动保存开启也不会在用户没点头时写盘。Ctrl+Z / Ctrl+Y 撤销重做不受影响。
- **文档类型显式化**：草稿 / 本地文件 / 云端文档现在是显式属性，不再靠“有没有路径”猜；云文档不参与本地草稿恢复。
- **草稿写入原子化**：`.tmp` + rename，崩溃不会留下半截 JSON 导致草稿整份丢失。

### 修复

- 修复关闭自动保存后，未保存草稿无法在重启时恢复的问题。
- 修复退出应用时“不保存”语义不一致：关闭单个标签页选「不保存」会删除草稿；退出应用不再默认丢弃草稿，保留/丢弃由用户明确选择。
- 修复自动保存开启时，AI 应用或格式转换结果被悄悄写盘的问题。
- 修复云文档被误当成本地草稿写草稿仓、重启后恢复成本地未命名标签页的问题。

# English

**Diagramon {{version}}** separates draft recovery from writing back to your files: drafts always come back; saved files are never rewritten behind your back.

### Downloads

| Type | File | Notes |
|---|---|---|
| **Installer** (recommended) | [`Diagramon_{{version}}_x64-setup.exe`]({{setup_url}}) (~{{setup_size_mb}} MiB) | Enables the **built-in auto-update**; if WebView2 is missing the installer downloads the runtime |
| **Portable** (no install) | [`Diagramon-{{version}}-win-x64.zip`]({{zip_url}}) (~{{zip_size_mb}} MB) | Unzip anywhere and run `diagramon.exe`; uninstall = delete the folder |

About the portable build: it ships `diagramon.exe` + `WebView2Loader.dll` + `ui\` + `assets\`, and those
**must stay together** (the `ui\` and `assets\` trees are read from disk, not embedded in the exe).
It needs **nothing extra installed**: no Node.js, no Chrome, no VC++ redistributable (the CRT is
statically linked) — only the system WebView2 runtime that comes with Windows 10/11.
The portable build's "Check for updates" still finds new versions, but updates use the **installer**
(it will not replace the portable folder in place) — keep using the portable form by downloading the new ZIP.

### Highlights

- **Draft recovery is back**: unsaved drafts with no local path (new documents, AI/conversion output) are written to the app data draft store and restored on next launch. This is **independent of the Autosave switch**.
- **Saved files are no longer touched by draft recovery**: local files are written back only when **Settings → Editor → Autosave (write to file)** is on; when off, edits stay in memory. Saved files **never enter the draft store**, so restarting no longer creates extra untitled copies.
- **Clear quit semantics**: when drafts exist, the quit dialog offers **Quit and keep drafts** or **Quit and discard drafts**. A synchronous flush runs before normal quit, so you don't get an older draft back.
- **AI / conversion output stays in memory**: AI "Apply to editor", AI-enhanced output, and format-conversion output are protected by `hold`; even with Autosave on they are not written until you save. Ctrl+Z / Ctrl+Y still work.
- **Explicit document kinds**: draft / local file / cloud document are now explicit properties, not inferred from "has a path"; cloud documents do not participate in local draft recovery.
- **Draft writes are atomic**: `.tmp` + rename, so a crash cannot leave half a JSON and lose the whole draft.

### Fixes

- Fixed unsaved drafts not being restorable after a restart when Autosave was off.
- Fixed inconsistent "don't save" semantics on quit: closing a tab with "Don't save" deletes its draft; quitting the app no longer silently discards drafts — keep or discard is your explicit choice.
- Fixed AI-applied or converted content being silently written when Autosave was on.
- Fixed cloud documents being treated as local drafts, written to the draft store, and restored as untitled local tabs.
