### 本次修复

- **Mermaid 转 Excalidraw 不再报「画布没有返回内容」**：以前转换后画布上其实已经画出来了，
  但客户端取不回产物，等十几秒后报错、新标签页是空的。原因是打包时用的是一份较早的承载页，
  「取回当前画布」这条指令从来没有进过安装包。现在转换完成后会正常取回并落盘。
- **含 `subgraph` 的 Mermaid 转到 Excalidraw 不再是一片空白**：上游解析器对 `subgraph` 只给一张
  整图位图，而这张图的数据此前在转换入口就被丢掉了，元素上的文件引用还被重新编号、对不上。
  现在位图能真正落到画布、也能存进文档；同时转换记录会写明**「该图已退化为位图，形状不能单独
  编辑，想要可编辑的形状请改选 drawio 或去掉 subgraph」**，不再让人对着空白猜。
- **打开含图片的 `.excalidraw` 文档能看到图片了**：这条与 Mermaid 无关——图片附件的字节从来没有
  交给画布，所以任何带图片的 Excalidraw 文档打开都是空的占位框。已修。
- **图片附件不再串到别的文档**：换到新文档后，上一份文档里的图片会被一起写进新文档的正文。
  现在只写入当前文档元素**真正引用到**的附件。

# English

**Diagramon {{version}}** fixes the "convert to Excalidraw" path end to end: three separate defects
kept it in a state where the canvas looked populated but the result could never be retrieved.

### Downloads

| Type | File | Notes |
|---|---|---|
| **Installer** (recommended) | [`Diagramon_{{version}}_x64-setup.exe`]({{setup_url}}) (~{{setup_size_mb}} MiB) | Enables the **built-in auto-update**; if WebView2 is missing the installer downloads the runtime |
| **Portable** (no install) | [`Diagramon-{{version}}-win-x64.zip`]({{zip_url}}) (~{{zip_size_mb}} MB) | Unzip anywhere and run `diagramon.exe`; uninstall = delete the folder |

About the portable build: it ships `diagramon.exe` + `WebView2Loader.dll` + `ui\` + `assets\`, and those
**must stay together** (the `ui\` and `assets\` trees are read from disk, not embedded in the exe).
It needs **nothing extra installed**: no Node.js, no Chrome, no VC++ redistributable (the CRT is
statically linked) — only the system WebView2 runtime that comes with Windows 10/11.
"Check for updates" still finds new versions, but updating downloads the **installer**
(it does not replace the portable folder in place) — to stay portable, grab the new ZIP manually.

### Fixes

- **Mermaid → Excalidraw no longer fails with "the canvas returned no content"**: the canvas used to
  render the diagram, but the client could not retrieve it; after ten-odd seconds it errored out and
  the new tab stayed empty. The packaged build was shipping an older canvas host page, so the
  "give me the current scene" command had never reached the installer. Conversion results are now
  retrieved and saved normally.
- **Mermaid with `subgraph` no longer turns into a blank canvas**: the upstream parser falls back to a
  single raster image for `subgraph`, and that image's data was dropped at the conversion entry point
  while the element's file reference was renumbered, so the two never matched. The bitmap now reaches
  the canvas and is saved into the document; the conversion log also states plainly that **the diagram
  was flattened to a bitmap, its shapes cannot be edited individually, and drawio (or removing
  `subgraph`) gives editable shapes** — no more guessing at a blank canvas.
- **Excalidraw documents containing images now show them**: unrelated to Mermaid — image bytes were
  never handed to the canvas, so any `.excalidraw` file with pictures opened as empty placeholders.
- **Image attachments no longer leak into other documents**: switching to a new document used to carry
  the previous document's images into the new file's body. Only attachments **actually referenced** by
  the current elements are written now.
