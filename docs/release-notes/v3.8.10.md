### 本次亮点

- **AI 面板不再卡在「正在等待模型…」**：3.8.9 起，凡是勾了「发送会话头」的 `opencode.ai` 地址，
  发请求时客户端会自锁死锁（设置锁不可重入，解析供应商时又去取了一次设置），于是对话永不结算，
  连设置窗口一起卡住。现在锁的持有范围收窄到取供应商那一段，AI 对话与设置窗口都正常。
- **`max_tokens` 越界自动纠偏**：严格型上游（DeepSeek 官方、opencode Go）遇到超过模型上限的值会
  直接 400 拒掉整轮，报文里带着自己的上限。客户端现在会从报文里读回上限，在**还没收到任何正文之前**
  用该上限重发一次；只重试一次，且**不回写设置**（那个值整个供应商共用，回写会把一个模型的上限变成全家的上限）。
- **`max_tokens` 可以留空**：设置里留空 = 请求里不发这个字段，交给上游按所选模型自己的默认/上限决定
  （推荐）。各家模型上限不同，而供应商的模型列表不返回上限，以前新建供应商默认填 500000，
  填大了严格型上游 400、填小了宽容型上游静默截断。现在新建供应商/加模型默认留空。

### 修复

- 设置里填非法的「最大 Tokens」不再被静默夹取到 1000000：会给中英提示并保留原值。
- 「最大 Tokens」输入框加了说明与「留空」占位提示，写清楚留空的语义。

# English

**Diagramon {{version}}** fixes a deadlock that left AI chat waiting forever on opencode.ai endpoints,
and stops `max_tokens` from being a number every user has to guess.

### Downloads

| Type | File | Notes |
|---|---|---|
| **Installer** (recommended) | [`Diagramon_{{version}}_x64-setup.exe`]({{setup_url}}) (~{{setup_size_mb}} MiB) | Enables the **built-in auto-update**; if WebView2 is missing the installer downloads the runtime |
| **Portable** (no install) | [`Diagramon-{{version}}-win-x64.zip`]({{zip_url}}) (~{{zip_size_mb}} MB) | Unzip anywhere and run `diagramon.exe`; uninstall = delete the folder |

About the portable build: it ships `diagramon.exe` + `WebView2Loader.dll` + `ui\` + `assets\`, and those
**must stay together** (the `ui\` and `assets\` trees are read from disk, not embedded in the exe).
It needs **nothing extra installed**: no Node.js, no Chrome, no VC++ redistributable (the CRT is
statically linked) — only the system WebView2 runtime that comes with Windows 10/11.
"Check for updates" still finds new versions, but updating downloads the **installer**
(it does not replace the portable folder in place) — to stay portable, grab the new ZIP manually.

### Highlights

- **The AI panel no longer hangs on "waiting for the model…"**: since 3.8.9, any `opencode.ai` endpoint
  with "send session header" enabled deadlocked the client (the settings mutex is not reentrant and was
  taken a second time while resolving the provider), so the request never settled and the settings
  dialog froze with it. The lock is now held only for the provider lookup.
- **Automatic `max_tokens` recovery**: strict upstreams (DeepSeek official, opencode Go) reject an
  out-of-range value with a 400 for the whole round, and their message states their own ceiling. The
  client now reads that ceiling and resends once with it — only before any content has arrived, at most
  once, and it never writes the value back to settings (that field is shared by every model on the
  provider, so writing back would turn one model's ceiling into everyone's).
- **`max_tokens` can be left blank**: blank means the field is not sent at all and the upstream applies
  the selected model's own default/ceiling (recommended). Model ceilings differ and the provider's model
  list does not expose them; the old default of 500000 was rejected by strict upstreams when too large
  and silently truncated by lenient ones when too small. New providers and new models now start blank.

### Fixes

- An invalid "Max tokens" value is no longer silently clamped to 1000000: the dialog explains the rule
  (in Chinese and English) and keeps the previous value.
- The "Max tokens" field now carries a hint and a "blank" placeholder that spell out what blank means.

Rendering and validation work with no network at all — code or images reach a model only when you
actively use AI, and then only the endpoint you chose.

Official website: <https://www.diagramon.com>
