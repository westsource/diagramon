### 本次亮点

  发出去的图片、AI 给的代码卡、思考过程各自跟着自己那一侧。明暗两套主题各有配色，看起来就像在聊天。
- **「截取屏幕区域识别」修好了**（本版重点）：以前点一下，**整块屏幕会变白**、框选拖不动、
  连主界面也一起卡死（只能杀进程）。现在点下去就正常出现冻结的屏幕画面，框选完直接进识图。
- **框选窗口更稳**：窗口建好之前不显示、底色不再白闪；万一 WebView2 起不来，也只留一条错误提示，
  不会再糊住整块屏幕。

### 修复

- **点「截取屏幕区域识别」导致整屏变白、无法框选、主界面失去响应**。
  根因是**在同步命令里创建窗口**：同步命令跑在 UI 主线程上，而建窗本身要等事件循环处理并回话 ——
  主线程自己等自己，于是窗口的框出来了、里面的页面永远建不出来（露出一整屏白），
  且整个应用不再响应任何请求。改成异步命令后主线程腾得出来，链路恢复正常。
- **自检/调试跑法下框选窗口的页面永远建不出来**：overlay 没带上与主窗口一致的 WebView2 参数，
  同一份用户数据目录上二次建环境会被直接拒绝（`ERROR_INVALID_STATE`）。现已与主窗口逐字一致。
- **框选失败不再留下一块关不掉的白色窗口**：窗口先隐藏、建成功再显示；失败时清掉冻结帧并如实报错。
- 对话里用户那一侧的称呼改为「我」（英文界面为「Me」）。

# English

**Diagramon {{version}}** turns the AI conversation into a WeChat-style chat and fixes the screen-capture
whiteout that could lock up the whole screen.

### Downloads

| Type | File | Notes |
|---|---|---|
| **Installer** (recommended) | [`Diagramon_{{version}}_x64-setup.exe`]({{setup_url}}) (~{{setup_size_mb}} MiB) | Enables the **built-in auto-update**; if WebView2 is missing the installer downloads the runtime |
| **Portable** (no install) | [`Diagramon-{{version}}-win-x64.zip`]({{zip_url}}) (~{{zip_size_mb}} MB) | Unzip anywhere and run `diagramon.exe`; uninstall = delete the folder |

About the portable build: it ships `diagramon.exe` + `WebView2Loader.dll` + `ui\` + `assets\`, and those
**must stay together** (the `ui\` and `assets\` trees are read from disk, not embedded in the exe).
It needs **nothing extra installed**: no Node.js, no Chrome, no VC++ redistributable (the CRT is
statically linked) — only the system WebView2 runtime that comes with Windows 10/11.
"Check for updates" still finds new versions, but updating downloads the **installer**
(it does not replace the portable folder in place) — to stay portable, grab the new ZIP manually.

### Highlights

- **WeChat-style AI chat**: everything you say sits on the **right** (green bubble, avatar labelled
  "Me"), the assistant on the **left**; attached images, generated code cards and the thinking log all
  follow their own side. Both light and dark themes have their own palette — it now reads like a chat.
- **"Capture screen region" is fixed** (the headline of this release): it used to turn the **entire
  screen white**, refuse to let you drag, and freeze the main window (kill-the-process kind of freeze).
  It now shows the frozen screen immediately, and the region you drag goes straight into vision.
- **A sturdier capture overlay**: the window stays hidden until it is actually ready and no longer
  flashes white; if WebView2 ever fails, you get an error toast instead of a white screen covering
  everything.

### Fixes

- **Clicking "Capture screen region" whited out the screen, blocked capture and froze the app.**
  Root cause: the window was created from a **synchronous command**, which runs on the UI thread,
  while window creation waits for the event loop to answer — the thread waited on itself. The frame of
  the overlay appeared, its page could never be created (leaving a full-screen white rectangle), and the
  app stopped answering every request. The command is now asynchronous, so the UI thread is free to
  serve the creation message.
- **Under self-test/debug runs the overlay page could never be created**: the overlay was missing the
  WebView2 arguments the main window uses, and creating a second environment on the same user-data
  folder with different options is rejected outright (`ERROR_INVALID_STATE`). Both windows now pass the
  exact same arguments.
- **A failed capture no longer leaves an unclosable white window**: the window is created hidden and
  shown only on success; on failure the frozen frame is dropped and the error is reported.
- The user side of the conversation is now labelled "Me" (「我」 in the Chinese UI).
