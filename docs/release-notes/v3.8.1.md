### 修复

- **导出的 PNG 是空白**：两条成因都修了。①文本型导出直接把 SVG 画到画布上，
  产出的 PNG **全透明** —— 暗色主题（浅色笔画）在白色看图器里几乎一片空白；
  ②图大到越过浏览器画布上限（面积 2^28 像素、单边 65535）时，绘制会被**静默跳过**、
  交回一张空图。现在位图带与预览一致的底色；超大图自动压倍率并在状态栏写明
  「已按 N× 导出（原计划 M×）」，而不是给你一张糊图或空图。「复制图片到剪贴板」同样受益
- **「最近打开」的时间显示成几万天前**：写入用的是秒、界面按毫秒读。已统一成毫秒
- **切视图模式 / 选布局时标签条会多出一个空标签**：这两条命令的返回值与前端约定不一致，
  真机上每次操作都会往会话里塞一个空对象。现在返回值统一成文档本身

# English

**Diagramon {{version}}** fixes the two things users hit most often — exported PNGs are no longer
blank, and "recently opened" timestamps no longer read as tens of thousands of days ago — and pushes
AI context one step further: external files can be dropped straight into the chat as reference, and
**each file remembers the look and layout you picked for it**.

### Downloads

| Type | File | Notes |
|---|---|---|
| **Installer** (recommended) | [`Diagramon_{{version}}_x64-setup.exe`]({{setup_url}}) (~{{setup_size_mb}} MiB) | Enables the **built-in auto-update**; if WebView2 is missing the installer downloads the runtime |
| **Portable** (no install) | [`Diagramon-{{version}}-win-x64.zip`]({{zip_url}}) (~{{zip_size_mb}} MB) | Unzip anywhere and run `diagramon.exe`; uninstall = delete the folder |

About the portable build: it ships `diagramon.exe` + `WebView2Loader.dll` + `ui\` + `assets\`, and those
**must stay together** (the `ui\` and `assets\` trees are read from disk, not embedded in the exe).
It needs **nothing extra installed**: no Node.js, no Chrome, no VC++ redistributable (the CRT is
statically linked) — only the system WebView2 runtime that comes with Windows 10/11.
"Check for updates" still finds new versions, but updating downloads the **installer**
(it does not replace the portable folder in place) — to stay portable, grab the new ZIP manually.

### Highlights

**AI can read your files now**

- **External files as context** — drop a file **onto the AI panel**, paste a full path under the
  composer, or use the folder button: up to 8 files, 256 KiB each (larger ones are cut on a character
  boundary and labelled), UTF-8 text only (binary or other encodings report a clear error). Reference
  files and the "current diagram source" are worded separately, so the model does not treat your
  reference as the document to rewrite
- **"Use current diagram as context" takes the editor buffer** — unsaved edits go to the model too;
  to point the model at *another file on disk*, use the external-file entry above (it reads the file
  at attach time — re-attach after the file changes)

**Every file remembers its look and layout**

- Pick a look (classic / neo / handDrawn) and a layout engine (dagre / elk / dot / neato …) in the
  preview top bar and they **stay with that file**: close the tab, restart the app, reopen it from the
  workspace or the recent list — same choice. "Save as" carries it along
- Keyed by **path** (case and slash direction mean the same file), stored in `render-opts.json`.
  Unsaved tabs have no path, so they cannot be remembered until saved

### Fixes

- **Exported PNG came out blank** — both causes fixed. ① The text-format export drew the SVG onto a
  canvas with **no background**, so the PNG was fully transparent: in a dark theme (light strokes) it
  looks like a blank page in any white viewer. ② Past the browser's canvas limit (2^28 pixels of area,
  65535 per side) the draw was **silently skipped** and an empty image came back. Bitmaps now carry the
  same background as the preview, and oversized diagrams have their scale reduced with a note in the
  status bar ("exported at N×, planned M×") instead of a blurry or empty image. "Copy image" benefits too
- **"Recently opened" showed timestamps tens of thousands of days ago** — written in seconds, read as
  milliseconds. Now consistently milliseconds
- **Switching view mode or layout added an empty tab** — those two commands returned a value the
  front-end did not expect, so every real-machine action pushed an empty object into the session.
  Both now return the document itself
