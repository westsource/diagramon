### 本次亮点

- **转换时可以换个布局引擎试试**：Mermaid 转 drawio 的对话框里多了一个「用 ELK 重排」，勾上就由
  drawio 自带的 ELK layered 引擎排图。回边不再绕大圈、边交叉明显减少，中等规模的流程图比默认的
  dagre 更接近人工调完的样子。这个开关记着你的选择，下次转换不用重新勾。
- **不勾就和以前完全一样**：默认关，走原来那套 dagre，已习惯的画法不受影响。
- **哪些情况没生效，会如实告诉你**：转换记录里会写明这次到底用没用 ELK —— 用了、源文件本来就有
  `layout: elk`、源文件已经有 `config` 段（再插会造成重复键，所以跳过）、或者目标不是流程图。
  这些都不静默略过。

### 修复

- **从第二个转换开始画布不刷新**：连续把两份文件转到 drawio（或 Excalidraw）时，第二个标签页显示的
  还是第一张图；两个画布标签之间来回切换也一样。根因是切文档时把「画布已就绪」清掉了，而承载页的
  就绪信号只在启动时发一次，于是后续的载入指令排在队列里再没发出去。已修（同 {{version}} 一起发）。
- **关闭画布标签后的残留载荷**：关掉最后一个同格式的画布标签时，会顺手清掉那次待用的转换载荷，
  避免下次新建同格式文档被误灌上一次的内容。

### 说明

- 「用 ELK 重排」只对 **Mermaid → drawio** 的流程图有意义：ELK 是 drawio 导入器内部的布局，

- 它不改变「文档级布局」的语义 —— 预览里选的布局仍然是预览自己的事，转换按这个开关来。

# English

**Diagramon {{version}}** adds a "Re-layout with ELK" option when converting to drawio: with it on, drawio's own ELK layered engine arranges the diagram, cutting back-edge detours and edge crossings noticeably.

### Downloads

| Type | File | Notes |
|---|---|---|
| **Installer** (recommended) | [`Diagramon_{{version}}_x64-setup.exe`]({{setup_url}}) (~{{setup_size_mb}} MiB) | Enables the **built-in auto-update**; if WebView2 is missing the installer downloads the runtime |
| **Portable** (no install) | [`Diagramon-{{version}}-win-x64.zip`]({{zip_url}}) (~{{zip_size_mb}} MB) | Unzip anywhere and run `diagramon.exe`; uninstall = delete the folder |

About the portable build: it ships `diagramon.exe` + `WebView2Loader.dll` + `ui\` + `assets\`, and those
**must stay together** (the `ui\` and `assets\` trees are read from disk, not embedded in the exe).
It needs **nothing extra installed**: no Node.js, no Chrome, no VC++ redistributable (the CRT is
statically linked) — only the system WebView2 runtime that comes with Windows 10/11.
"Check for updates" still finds new versions, but updating downloads the **installer**
(it does not replace the portable folder in place) — to stay portable, grab the new ZIP manually.

### Highlights

- **Try a different layout engine right in the conversion dialog**: Mermaid → drawio now has a
  "Re-layout with ELK" switch. With it on, drawio's own ELK layered engine arranges the diagram —
  back edges stop taking the long way round and edge crossings drop, so medium-sized flowcharts land
  much closer to a hand-tuned result than the default dagre. The switch remembers your choice.
- **Off by default, so nothing changes unless you ask**: unchecked, it is exactly the old dagre path.
- **When it does not apply, you are told**: the conversion record says what actually happened — applied,
  the source already declared `layout: elk`, the source already had a `config` block (injecting another
  would duplicate a key, so it was skipped), or the target is not a flowchart. None of these are silent.

### Fixes

- **Canvas did not refresh from the second conversion on**: converting two files to drawio (or
  Excalidraw) in a row left the second tab showing the first diagram; switching between two canvas
  tabs had the same problem. The readiness flag was cleared when switching documents, while the host
  page only sends that signal once at startup, so later load commands sat in the queue forever. Fixed
  (shipped together in {{version}}).
- **Stale pending payload after closing a canvas tab**: closing the last canvas tab of a format now also
  drops that pending conversion payload, so a new document of the same format cannot inherit it.

### Notes

- "Re-layout with ELK" only applies to **Mermaid → drawio** flowcharts: ELK lives inside drawio's
  importer, and the Excalidraw chain uses a different importer that does not read this config.
- It does not change what document-level layout means — the layout you pick in the preview is still
  the preview's business; conversion follows this switch.
