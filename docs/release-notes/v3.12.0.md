**Diagramon {{version}}** 给图表加了一套"自动配色"：AI 不再随手写色值，而是只标角色；颜色由本地按色系展开，可复现、可一键换、也可以只留在预览里。

### 本次亮点

- **AI 只标角色，色值本地落地**：模型写"主链路 / 入口 / 判断 / 数据 / 外部 / 异常 / 说明"，应用按色系把角色展开成色值 ——
  同一句话两次生成不会出现两套颜色，暗色主题也自动用更亮的一档。跨格式一致：Mermaid / DOT / D2 都能落地。
- **六种色系 + 线框档**：松绿 / 黛蓝 / 藕紫 / 橄榄 / 赭石 / 钨灰（无彩，线框与打印）。预览顶栏第三颗按钮切换，
  **按文件记住**；连线一起跟随色系（设置里可关）。
- **打开即挑选**：打开没有记过色系的文件时，按图里的角色占比与标签本地选一个（数据/存储多→黛蓝、异常多→赭石、
  外部接口多→橄榄、界面词→藕紫，否则松绿），状态栏写明依据。**新建文档默认「无」。**
- **颜色只留在预览里**：换色系、换主题都不改正文；想固化给别人看，菜单里有「写入正文」。
  清除（「无」）也只改缓冲区 —— 磁盘要你自己保存。
- **「无」会尽量清干净**：先删程序生成的那一段；如果正文里还有手写/外来颜色，且配置了模型，
  就让模型只删颜色（结构一改就放弃这次清理）。
- **更安静的资料**：连线默认跟随色系但压低饱和度；色系之间按可辨识度重新排过（同一色系内七个角色
  填充最小色差从 1.2 提到 3.6–5.9，换色系的差异从 2 提到 17）。

### 修复

- Mermaid 里带连字符的类名（`A[开始]:::my-class --> B`）不再让整份文件解析失败。
- 节点在边上被再次提及时，形状不再被覆盖成方框（判断/圆柱节点之前会被当成主链路）。
- 自动配色失败不再挡住渲染：出图照常，原因写在状态栏。
- 便携版的 README 截图在缺少 ELK 离线包时会显示"加载失败"，已修（截图脚本补上挂载点）。

# English

**Diagramon {{version}}** adds automatic colouring: the AI no longer invents hex values, it only tags roles; the app expands them into a palette — reproducible, swappable in one click, and optionally preview-only.

### Downloads

| Type | File | Notes |
|---|---|---|
| **Installer** (recommended) | [`Diagramon_{{version}}_x64-setup.exe`]({{setup_url}}) (~{{setup_size_mb}} MiB) | Enables the **built-in auto-update**; if WebView2 is missing the installer downloads the runtime |
| **Portable** (no install) | [`Diagramon-{{version}}-win-x64.zip`]({{zip_url}}) (~{{zip_size_mb}} MB) | Unzip anywhere and run `diagramon.exe`; uninstall = delete the folder |

About the portable build: it ships `diagramon.exe` + `WebView2Loader.dll` + `ui\` + `assets\`, and those
**must stay together** (the `ui\` and `assets\` trees are read from disk, not embedded in the exe).
It needs **nothing extra installed**: no Node.js, no Chrome, no VC++ redistributable (the CRT is
statically linked) — only the system WebView2 runtime that comes with Windows 10/11.
"Check for updates" still finds new versions, but updating downloads the **installer**
(it does not replace the portable folder in place) — to stay portable, grab the new ZIP manually.

### Highlights

- **The AI tags roles, the app picks the colours** — the model writes main / entry / decision / data /
  external / failure / note, and the palette expands those into values: the same sentence never yields two
  different palettes, and dark themes get the brighter ladder automatically. The same tags work in Mermaid,
  DOT and D2.
- **Six schemes plus a wireframe one** — Pine / Indigo / Lotus / Olive / Ochre / Tungsten (achromatic, for
  wireframes and print). Switch from the third control in the preview toolbar; the choice is **remembered per
  file**, and edges follow the scheme too (switchable in Settings).
- **Picked on open** — a file with no remembered scheme gets one chosen locally from its role mix and labels
  (data-heavy → Indigo, failures → Ochre, many external calls → Olive, UI wording → Lotus, otherwise Pine),
  with the reason shown in the status bar. **New documents start with None.**
- **Colours live in the preview** — switching scheme or theme never rewrites the source; 「Bake into source」
  is there when you want the colours in the file. Clearing (「None」) only touches the buffer, too — saving
  stays your call.
- **「None」 tries to leave nothing behind** — our own block goes first; if hand-written or foreign colours
  remain and a model is configured, the model strips colours only (and the cleanup is discarded if it
  changes the structure).
- **Quieter diagrams** — edges follow the scheme at reduced saturation, and the schemes were re-spaced by
  measured distance (role fills went from ΔE 1.2 to 3.6–5.9, scheme-to-scheme from 2 to 17).

### Fixes

- Mermaid class names containing hyphens (`A[开始]:::my-class --> B`) no longer break the whole file.
- A node mentioned again on an edge keeps its shape (decision/cylinder nodes were being treated as main path).
- A failed palette expansion no longer blocks rendering: the diagram still draws and the reason lands in the
  status bar.
- The README screenshots no longer show an ELK "failed to load" message (the capture script now serves the
  bundled ELK chunk).
