### 本次亮点

- **连续转换不再串图**：打开两个 Mermaid 文件、依次转成 drawio，第二个标签页现在显示的是它自己的图，
  不再是第一张。这里原本是画布就绪状态的判断写错了——切换文档时把「已就绪」重置了，但承载页
  的就绪信号只在启动时发一次，于是第二次的载入指令被排进队列后再也没人送出。
- **多标签切换同步修好**：同一处判断也让「在两个 drawio 标签之间来回切」显示错误的图，一并修掉了。
- **关闭标签后不再残留**：关掉最后一个同格式的画布标签时，会顺手清掉那次待用的转换载荷，
  避免下次新建同格式文档时被误灌上一次的内容。

### 修复

- **第二次转换为 drawio / Excalidraw 时画布不更新**：转换到画布型格式时，第二次及以后的载入指令
  会被滞留在待发队列里永不执行，画布停留在上一份文档。现在只有承载页发出就绪信号时才标记就绪，
  切换文档不再重置它。
- **画布标签之间切换显示错误的图**：同上根因（就绪状态被误重置），切换标签后画布不重新载入正文。
- **关闭画布标签后的残留载荷**：待用的转换载荷按格式存放、且是单例；关掉实例后不清理，
  下次新建同格式文档会被误判成一次转换而灌入旧内容。现在随实例一起清理。

# English

**Diagramon {{version}}** fixes a canvas-hosting defect: converting two different files to drawio (or Excalidraw) one after another left the second canvas showing the first file's content.

### Downloads

| Type | File | Notes |
|---|---|---|
| **Installer** (recommended) | [`Diagramon_{{version}}_x64-setup.exe`]({{setup_url}}) (~{{setup_size_mb}} MiB) | Enables the **built-in auto-update**; if WebView2 is missing the installer downloads the runtime |
| **Portable** (no install) | [`Diagramon-{{version}}-win-x64.zip`]({{zip_url}}) (~{{zip_size_mb}} MB) | Unzip anywhere and run `diagramon.exe`; uninstall = delete the folder |

About the portable build: it ships `diagramon.exe` + `WebView2Loader.dll` + `ui\` + `assets\`, and those
**must stay together** (the `ui\` and `assets\` trees are read from disk, not embedded in the exe).
It needs **nothing extra installed**: no Node.js, no Chrome, no VC++ redistributable (the CRT is
statically linked) — only the system WebView2 runtime that comes with Windows 10/11.
"Check for updates" still finds new versions, but updating downloads the **installer**
(it does not replace the portable folder in place) — to stay portable, grab the new ZIP manually.

### Highlights

- **No more cross-wired conversions**: open two Mermaid files and convert them to drawio in turn — the
  second tab now shows its own diagram instead of the first one. The readiness check was wrong: switching
  documents cleared the "ready" flag, but the host page only sends that signal once at startup, so the
  second load command sat in the queue and never went out.
- **Switching between tabs is fixed too**: the same mis-set flag also made switching between two drawio
  tabs show the wrong diagram.
- **Nothing left behind after closing a tab**: closing the last canvas tab of a format now also drops that
  pending conversion payload, so a newly created document of the same format cannot be filled with it.

### Fixes

- **Second conversion to drawio / Excalidraw did not update the canvas**: from the second load onward the
  command was parked in the outbound queue forever and the canvas kept the previous document. Readiness is
  now set only when the host page reports it, and switching documents no longer clears it.
- **Switching between canvas tabs showed the wrong diagram**: same root cause (readiness wrongly cleared),
  the canvas did not reload the document body after a tab switch.
- **Stale pending payload after closing a canvas tab**: the pending conversion payload is keyed by format
  and is a singleton; it was not cleared when the host instance went away, so the next document of that
  format could be mistaken for a conversion and filled with old content. It is now cleared with the host.
