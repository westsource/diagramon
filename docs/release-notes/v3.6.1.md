### 本次亮点

- **DOT（Graphviz）预览恢复** —— 3.5.2 起没跑过一次的渲染路径：加载器把 vendor 路径按模块自身的 URL
  解析错了，动态导入 404，于是 DOT 文档一律显示「Graphviz 渲染不可用」；现在按模块位置解析，DOT 预览出图
- **失败提示不再误导** —— 以前不管什么原因都讲成「ES 模块在 file:// 下被浏览器拦截」，把一个纯路径 bug
  说成环境问题；现在提示里带**真实原因**，file:// 那条降级成附注

### 修复

- `ui/js/graphviz-loader.js`：`import()` 里的相对说明符相对**模块自身**解析（只有内联脚本时才恰好等于文档
  URL），外置之后 `./vendor/graphviz.js` 打到了不存在的 `/js/vendor/graphviz.js` ⇒ DOT 预览整片不可用。
  改为用 `import.meta.url` 拼绝对 URL
- 加载失败从 `console.warn` 提升为 `console.error`：静默降级正是它躲过整套探针的原因
- 报错文案带真实原因（`{msg}`），并新增「加载器未执行」这一条（中英成对）
- 回归防护：UI 探针新增断言 —— DOT 文档**必须真的出图**（只看「舞台里有 SVG」会被上一个文档的残留骗过）
- 影响范围：只有 DOT 受影响；Mermaid、drawio、Excalidraw、D2 都不受影响（Mermaid 走经典脚本、按文档解析，
  所以它一直正常）—— 这也是本问题能潜伏 9 个版本没被发现的原因

# English

**Diagramon 3.6.1** is a fix release: DOT (Graphviz) preview had been completely dead since 3.5.2 and works
again now; the "rendering unavailable" message also stops stating a cause it never checked.

### Downloads

| Type | File | Notes |
|---|---|---|
| **Installer** (recommended) | [`Diagramon_{{version}}_x64-setup.exe`]({{setup_url}}) (~{{setup_size_mb}} MiB) | Enables the **built-in auto-update**; if WebView2 is missing the installer downloads the runtime |
| **Portable** (no install) | [`Diagramon-{{version}}-win-x64.zip`]({{zip_url}}) (~{{zip_size_mb}} MB) | Unzip anywhere and run `diagramon.exe`; uninstall = delete the folder |

About the portable build: it ships `diagramon.exe` + `WebView2Loader.dll` + `ui\` + `assets\`, and those
**must stay together** (the `ui\` and `assets\` trees are read from disk, not embedded in the exe).
It needs **nothing extra installed**: no Node.js, no Chrome, no VC++ redistributable (the CRT is
statically linked) — only the system WebView2 runtime that comes with Windows 10/11.
"Check for updates" still finds new versions, but updating downloads the **installer**
(it does not replace the portable folder in place) — to stay portable, grab the new ZIP manually.

### Highlights

- **DOT (Graphviz) preview is back** — a render path that had not worked once since 3.5.2: the loader
  resolved its vendor path against the module's own URL instead of the document, the dynamic import
  404'd, and every DOT document showed "Graphviz rendering unavailable". It resolves correctly now.
- **Honest failure messages** — every failure used to be described as "ES modules are blocked under
  file://", turning a plain path bug into an environment story; the message now carries the **real
  reason** and demotes the file:// note to a footnote.

### Fixes

- `ui/js/graphviz-loader.js`: a relative specifier inside `import()` resolves against the **module's own
  URL** (it only coincides with the document URL while the script is inline). Once the script moved to
  its own file, `./vendor/graphviz.js` hit a non-existent `/js/vendor/graphviz.js` ⇒ DOT preview died.
  It now builds an absolute URL from `import.meta.url`.
- Loader failure is reported with `console.error` instead of `console.warn` — the silent downgrade is
  exactly why the whole probe suite stayed green.
- The unavailable-rendering message includes the real reason (`{msg}`), plus a new "loader did not run"
  case (both ZH and EN).
- Regression guard: the UI probe now asserts that a DOT document **actually renders a diagram** (merely
  finding an SVG on the stage was satisfied by leftovers from the previous document).
- Scope: DOT only. Mermaid, drawio, Excalidraw and D2 were never affected (Mermaid runs as a classic
  script and resolves against the document, which is why it kept working) — and that asymmetry is why
  the bug survived nine releases unnoticed.

### About Diagramon

Diagramon is a **local-first** multi-format diagram editor: Mermaid, Graphviz DOT, D2, drawio and Excalidraw
can all be edited with live preview, with AI assistance for generation, review and image recognition.
Rendering and validation work with no network at all — code or images reach a model only when you
actively use AI, and then only the endpoint you chose.

Official website: <https://www.diagramon.com>

- **No** Node.js, Chrome or VC++ redistributable needed — the canvas runtimes and front-end assets all
