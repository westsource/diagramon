### 修复

- **两端端点标记不再让整条语句报错**：`EDGE <-->|跨网 MQTT 通道| EMQX` 是合法 Mermaid
  （flowchart 词法规则 `[xo<]?--+[-xo>]`），但转换器的连接件解析只认六个箭头 token，
  端点标记压根没进词法 —— 于是整行被判成「语句尾部有没解析完的内容」，DOT 与 D2 两个方向
  共用同一套解析，所以两处都报同一句话。现在：
  - `<-->` 转成 DOT 的 `dir=both`、D2 的 `<->`（起点与终点同为「两端」时才成立，
    判定照 Mermaid 自己的口径：首位与末位字符同款才算两端都有 —— `x--o` 只认末位那个圈、
    `<--` 连端点都没有，不自己发明语义）；
  - `o--o` / `x--x` / `--o` / `--x` 的圆圈与叉在 DOT、D2 里**都没有对应形状**，退化成
    不带端点的普通边，并在**转换记录里逐条写明**（不静默丢）。
- **DOT 关键字不再让产物编译不过**：DOT 的关键词大小写无关（`node` / `edge` / `graph` /
  `digraph` / `subgraph` / `strict`），而 Mermaid 里起名叫 `EDGE` 很常见 —— 裸写出去
  graphviz 直接 syntax error。现在这些名字加引号（`graph1` 这类照旧裸写，产物更好读）。
- **D2 的 `stroke-width` 带上单位不再编译失败**：D2 只接受 **0–15 的整数**，而 Mermaid 写的是
  `2px` / `1.5px`。现在去单位、四舍五入、按上限截断，**改动过的原值进转换记录** ——
  以前这种情况产物在 D2 里根本编译不过。

# English

**Diagramon {{version}}** does one thing: it fixes three ways Mermaid → DOT / D2 conversion could
produce broken output. It started with a real document (`服务区数据接入.mmd`) that failed in both
directions with the very same error.

### Downloads

| Type | File | Notes |

About the portable build: it ships `diagramon.exe` + `WebView2Loader.dll` + `ui\` + `assets\`, and those
**must stay together** (the `ui\` and `assets\` trees are read from disk, not embedded in the exe).
It needs **nothing extra installed**: no Node.js, no Chrome, no VC++ redistributable (the CRT is
statically linked) — only the system WebView2 runtime that comes with Windows 10/11.
"Check for updates" still finds new versions, but updating downloads the **installer**

### Fixes

- **Endpoint markers no longer break the whole statement.** `EDGE <-->|跨网 MQTT 通道| EMQX` is valid
  Mermaid (the flowchart lexer accepts `[xo<]?--+[-xo>]`), but the converter's link parser only knew
  six arrow tokens — the endpoint markers never made it into the lexer, so the line was rejected as
  "trailing content after the statement". DOT and D2 share one parser, hence the identical error in
  both. Now:
  - `<-->` becomes DOT `dir=both` / D2 `<->` (only when both ends carry the same marker — decided the
    way Mermaid itself does it: only a matching first and last character counts as double-ended, so
    `x--o` keeps just the final circle and `<--` has no endpoints at all; no invented semantics);
  - the circle and cross of `o--o` / `x--x` / `--o` / `--x` have **no counterpart** in DOT or D2, so
    they degrade to a plain edge with **no marker** — and the conversion record says so line by line
    (nothing is dropped silently).
- **DOT keywords no longer break the output.** DOT keywords are case-insensitive (`node` / `edge` /
  `graph` / `digraph` / `subgraph` / `strict`) and naming a node `EDGE` in Mermaid is perfectly normal —
  emitted bare, graphviz fails with a syntax error. Such names are quoted now (`graph1` and friends stay
  bare, which keeps the output readable).
- **D2 `stroke-width` with a unit no longer fails to compile.** D2 accepts **integers 0–15** only, while
  Mermaid writes `2px` / `1.5px`. The unit is stripped, the value rounded and clamped to the maximum,
  and **any changed original goes into the conversion record** — previously such output could not be
  compiled by D2 at all.
