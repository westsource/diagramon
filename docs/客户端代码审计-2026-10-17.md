## 高危

### F-1 `dgm` 协议路径穿越：`%5C`（`\`）绕过 `..` 检查（Windows）

**位置**：`crates/assets/src/lib.rs` `resolve()` 第 116–139 行。

```rust
if decoded.split('/').any(|seg| seg == "..") {
    return None;   // 只挡 '/' 分隔的 ..
}
...
let candidate = dir.join(rel);
candidate.is_file().then_some(candidate)
```

**问题**：百分号解码 `%5C` → `\` 之后，`..` 检查仍然只按 `/` 切分；而 Windows 上 `Path::join` 把 `\` 当分隔符，`..` 段会穿透挂载根。

**实证**（用同逻辑复刻编译运行）：

```
输入  /drawio/..%5Csecret%5Cwin.ini
返回  Some("...\drawio\..\secret\win.ini")   ← 已落到挂载目录之外
输入  /drawio/../../secret/win.ini
返回  None                                    ← 正斜杠的检查是好的
```

**利用链**：webview 内任何脚本执行（恶意图表文件、渲染引擎 XSS）都可以
`fetch('http://dgm.localhost/drawio/..%5C..%5CUsers/...')` 读任意本机文件——
协议处理器不校验调用来源，页面脚本同源可达。CSP 为 null（F-2）让这条链更容易成立。

**修法**（一行 + 测试）：

```rust
// 反斜杠不是合法的 URL 路径字符：直接拒绝（资产树里也没有带 \ 的文件名）
if decoded.contains('\\') {
    return None;
}
```

并补两条测试：`resolve(&r, "/drawio/..%5Csecret")` 与 `/..%5C..%5Csecret` 均为 `None`。

## 中危

### F-2 CSP 为 null + 渲染产物直插 innerHTML

**位置**：`src-tauri/tauri.conf.json`（`csp: null`、`withGlobalTauri: true`）；`ui/js/preview.js:449`（`stage.innerHTML = svgText`）；`ui/index.html` 无 CSP meta。

现状：mermaid 用了 `securityLevel: "strict"`（好）；但 graphviz wasm 与 D2 wasm 的 SVG 输出**未做任何过滤**就 innerHTML 插入，SVG 的事件属性（`onbegin` 等）经 innerHTML 插入是会执行的。三个渲染引擎都依赖上游自己的转义纪律，本应用没有第二道防线。

而 `withGlobalTauri: true` 把整个 Tauri API 挂在 `window.__TAURI__` 上一旦有 XSS，攻击面直接包括：全部 invoke 命令（含 F-3 的任意写）、opener、剪贴板、以及 F-1 的任意读。

**建议**（按性价比排序）：
1. 给 `ui/index.html` 与两个承载页加 CSP：`default-src 'self' dgm:; script-src 'self' dgm: 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' dgm: data:`（graphviz wasm 需要 `wasm-unsafe-eval`；先在 `tauri.conf.json` 的 `app.security.csp` 配，再逐页核对 vendor 脚本加载）。
2. `mountSvg` 里把 `svgText` 先过 DOMParser（`image/svg+xml`）再挂载，丢弃含 `<script>` 与事件属性属性的节点（toPngDataUrl 已经在用 DOMParser，模式现成）。

### F-3 `export_write` / `doc_save_as` 任意路径写

**位置**：`src-tauri/src/commands.rs`。

`check_writable` 只在 `restrict_to_workspace` 开启时生效（默认关，注释说明是有意为之——「另存为」是用户授权）。但 F-2 一旦成立，这里就是"任意路径写文件"原语。**建议**：`export_write` 对扩展名做白名单（png/svg/jpeg），另存为维持现状（真用户走系统对话框）。

## 低危 / 建议

- **F-4** `atomic_write` 用 `path.with_extension("dgm-tmp")`：`a.mmd` 的临时文件是 `a.dgm-tmp`。同目录下 `foo.mmd` 与 `foo.drawio` 并存且同时保存时会互踩临时文件（rename 竞态）。建议换成追加式后缀（`format!("{name}.dgm-tmp")` + 随机/pid 区分）。
- **F-5** `lib.rs::open_cli_files` 只过滤 `-` 开头参数，不过滤扩展名；单实例路径 `diagram_files` 过滤了。两处应统一（后者是对的：避免把 exe 路径、垃圾参数塞进会话）。
- **F-6** `shell.js::esc` 不转义 `'`。当前所有模板属性都是双引号包裹，无实际漏洞；但新增代码若用单引号属性就会中招。建议补 `"'": "&#39;"`。
- **F-7** `ai.js:134` `m.image.dataUrl` 未 esc 直插 `src="…"`。当前 dataUrl 全部来自本地截屏/文件选择器；若未来支持粘贴远程图或云文档带图，这里要再审。
- **F-8** `cloud.rs` 把 `doc_id.trim()` 直接 `format!` 进 URL。id 目前由服务端/本机 uuid 生成，但防御性 urlencode 一下更稳（`/documents/{id}` 两处）。
- **F-9** `preview.js` 导出时用户取消保存对话框会兜底写到硬编码的 `E:/OpenCode/diagramon/export/`。开发残留，产品里应改为"取消即不导出"。

## 架构备注（本次未动，需要单独立项）

**承载域分离**：`withGlobalTauri: true` + 外壳与五个承载页**同源**（`dgm` 协议），意味着
drawio / Excalidraw 这些渲染**不可信内容**的 iframe realm 同样摸得到 `window.__TAURI__`
与全部 invoke 命令。外壳页的 CSP 管不到它们（那是独立文档），drawio 自身的
index.html 又是上游产物没法插 meta。真正的修法是把承载页挪到**另一个 origin**
（如第二个自定义协议 `dgm-canvas://`），让 iframe 跨源、靠 postMessage 通信 ——
这会推翻"同源让 iframe 通信不受限"的现有设计（`canvas.js` 直接读写
`win.__hostQueue`），动静大，值得单独立项评估。
