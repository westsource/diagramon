# 账户 / 云端文档 / 保存到云端 —— 界面原型说明

> **已实现（2026-10-11）**：本原型已落进 `client2/ui`。落点见本文 §三；
> 实现补充说明见 `docs/roadmap-dev3.0.md` 的「第 6 步补充 · 云端界面拆分」。
> 与原型的三处差异：
> ① 云端文档是**侧栏单栏统一树**（不做宽窗口双栏管理视图）；
> ② 保存窗口**只选目录**（不做右侧参照列表）；
> ③ 云端文档视图**不再显示存储用量**（额度归「账户」视图，见 §二.2）。
> 其余（含 AI 权益与额度）均已按原型实现。登录窗口按应用内对话框实现；
> 「注册地址」用只读输入框 + 复制按钮。

> 原型：`cloud-proto.html`（双击即可打开，`file://` 全功能可用）。
> 增量样式 `cloud-proto.css`、交互 `cloud-proto.js`，**都标了「实施时并入后删」**。
> 复用 `proto.css` + `proto-icons.js`，所以外观与 dev3.0 主界面一致。

## 一、这次要解决什么

现状（`ui/js/sidebar.js::viewCloud`）是**一个视图把三件事混在一起**：账户头 + 内联登录表单 + 文档列表；
而且活动栏的「云端文档」(Alt+4) 和底部的「账户与云端」按钮**指向同一个视图**。
本次拆成四块，各自只做一件事：

| # | 界面 | 入口 | 只做 |
|---|---|---|---|
| 1 | **账户**（侧栏视图，只读） | 活动栏底部「账户」 | 看邮箱 / 昵称 / 套餐（含 AI 权益）/ 存储与 AI 额度 |
| 2 | **云端文档**（侧栏视图，目录树） | 活动栏「云端文档」Alt+4 | 查找、打开云端文档 |
| 3 | **保存到云端**（窗口） | 文件菜单 →「保存到云端…」 | 选目录 + 文档名，落到指定目录 |
| 4 | **登录**（独立窗口） | 未登录时点「账户」；或各视图里的「登录」按钮 | 登录、重发激活邮件、跳官网注册 |

## 二、四个界面的设计要点

### 1. 账户（侧栏，只读）
- 账户卡片（头像 + 昵称 + 邮箱）→ 只读信息行（套餐 / 会员到期 / 角色 / **AI 服务** / 邮箱状态）→
  **存储用量**与 **AI 额度（本周期）**两条进度条（值全是服务端给的，`used / total` 两个数都写出来）→
  动作只有「刷新」「退出登录」。
- **AI 权益三态**，不能混：`ai.enabled = true` → 「已开通」；`= false` → 「未开通」；
  **整块缺失/为 null**（旧服务端）→ 「—」未知。把"不知道"画成"未开通"就是在说谎。
- **额度单位是「信用点」，不是人民币**：服务端给的是整数微信用点（1 微信用点 = 1e-6 信用点），
  且明确不把信用点锚定货币 —— 所以页面上一律写「信用点」。剩余额度是**减出来的**
  （服务端只给"总额 + 已用"：充值是加在总额上，所以 `总额 - 已用` 任何时候都成立）。
  周期结束日期照服务端的 `periodEnd` 显示成「周期至 X 重置」，不自己猜"下月 1 日"。
- **未登录时点活动栏的「账户」→ 直接弹登录窗口**（需求原文）；
  侧栏自己则显示「未登录」卡片 + 一个「登录」按钮。
- 页面明确写「账户信息只读，改昵称 / 改密码 / 充值请到官网账户页」—— 不在客户端开编辑口子（注册同理，见 §4）。
- 未配置网关时退化成「云网关未配置 / 去配置」，绝不显示假余额。

### 2. 云端文档（侧栏，目录树）
- **单栏统一树**：目录可展开（行首箭头 + 文件夹图标，展开/收起两种形态），
  文档是叶子（格式色点 + 名称 + 大小）。空目录淡显并标「空」——否则它和「没加载出来」长得一样。
- 顶部：筛选框（输入即过滤，命中片段高亮，命中的目录自动展开）+ 刷新 / 新建目录 / 保存到云端三个图标钮。
- 底部只报**本次树里的计数**（共 N 个文档 · M 个目录）—— **不显示存储用量**：额度是「账户」
  视图的事（同一份服务端数据），相邻两个视图各显示一遍同一个数字只会让人怀疑哪个才是真的。
- 点击文档 = 打开（真实走 `cloud_doc_open`，开成无路径标签页）。
- 视觉与文案**照服务端 `components/folder_tree.html`**：固定缩进、不画连接线、整行 hover/选中、
  行尾报「N 个文档 / 空」。
- 未登录时显示提示 + 登录按钮（**这里不自动弹窗** —— 只有「账户」按需求直接弹）。

### 3. 保存到云端（窗口）
- 顶部「文档名」（预填当前名，保存 + 改名一次请求搞定）；
- 中间**目录选择树**（单选，含「根目录」行；选中项有圆点与高亮）；
- 「在当前目录下新建子目录」+ 新建按钮（服务端 `POST /v1/folders`，空目录也能建）；
- 底部实时显示「目标目录：架构/后端」+ 取消 / 保存。
- 参照：旧客户端 `CloudPathPickerDialog.cs`（同一件事：选目录 + 定名字）。

### 4. 登录（独立窗口）—— **不做注册**
- 参照旧客户端 `client/Views/LoginDialog.cs`：邮箱 + 密码、错误区（红）/ 信息区（绿）、
  「重发激活邮件」只在 `email_not_verified` 时出现。
- **注册不在客户端做**（已定）：注册、邮箱激活、条款/隐私文案都在网页端，
  客户端再实现一份就是**第三个要同步的地方**（服务端 / 网页 / 桌面端）—— 邮箱激活、重发、
  密码规则任意一处改动都会两端漂移。所以页脚只有「**没有账号？去官网注册**」这一个**导航动作**，
  不是第三个按钮（免得看起来像点它能在这里完成注册）。
- 点击后按 **`{服务根地址}/register`** 打开系统浏览器（地址由配置的服务端根地址推导，
  不硬编码域名 —— 联调 / 私有部署自动跟着走）；打不开浏览器时**把地址显示在信息区**让用户自己复制，
  静默失败等于按了没反应。
- 客户端**不做任何前置校验**（旧客户端的刻意决定：客户端拦一次就多一条会与服务端漂移的规则），
  只在空输入时给一句提示。密码强度文案里的数字由服务端给，不硬编码。
- 注册地址**回显成只读输入框 + 「复制」按钮**（不是一句纯文本）：`user-select: text`、点一下全选、
  「复制」先试同步的 `execCommand("copy")`、失败再退回异步 `navigator.clipboard`。
  用户要的是"能拷走"，光看得到没用。
- **登录成功要落到「用户点的那儿」**（原型 `cloud-proto.js`：`S.signedIn = true; S.view = "account"`）：
  登录只是中途一站。从活动栏「账户」进来的就切到账户视图；从「保存到云端」进来的就接着开保存窗口。
  实现时漏了这一步，症状是"登录完还停在资源浏览器，再点「账户」只弹一句已登录"
  （用户 2026-10-11 实测反馈）—— 原型行为是对的，**实现要照着它来**。

### 5. 全局统一会话（一处登录，处处生效）
- **只有一份登录状态**：`cloud_status` 是唯一真源（令牌在凭据库，不在前端）。
  「账户」和「云端文档」只是同一份状态的**两个视图**，都读它、都不自己存。
- 所以：在「账户」里登录后，切到「云端文档」**不会再要求登录**；在那边的「登录」按钮
  打开的是**同一个**登录窗口，成功后两个视图同时刷新（一次 `cloud:changed` 广播）。
- 反例（必须避免）：各视图各存一个 `signedIn` 副本 —— 那样"登录了两处只有一处生效"
  这类 bug 会反复出现，而且没有任何守卫能拦住。

## 三、实施映射（确认后按这个改）

| 落点 | 改什么 |
|---|---|
| `ui/js/sidebar.js` | `viewCloud()` 拆成 `viewAccount()` + `viewCloudDocs()`；视图表 `VIEWS` 加 `account` |
| `ui/js/shell.js` | `ACTS` 不动（仍 5 项）；底部账户钮改指向 `account` 视图、tooltip 由「账户与云端」改「账户」；`Alt+4` 仍是云端文档 |
| `ui/js/shell.js` 文件菜单 | 「保存到云端…」从 `disabled` 改开保存窗口；「云端文档…」改开云端文档视图 |
| 新增 `ui/js/cloud.js` | 登录窗口、保存窗口、目录树组件（两个窗口共用） |
| `ui/js/state.js` | `cloudFolders()`；`cloudSaveActive(path, name)` |
| `crates/app-ipc` | 新增 `CloudFolder` / `cloud_folders`（镜像 `GET /v1/folders`）；`cloud_doc_save` 增加 `path` 参数 |
| 打开注册页 | 走 Tauri opener 打开 `{cloud.base_url}/register`；打不开时把地址回显在登录窗口里 |
| `ui/i18n.js` | 新增 `acct.*` / `cloud.*` 词条；`set.tab.cloud` 的「账户与云端」保留给设置页 |

**为什么必须加 `cloud_folders`**：现在客户端只有 `cloud_docs_list`（列表里带 `path`，
但没有目录全集），**空目录根本列不出来**，树就没法建。服务端 `GET /v1/folders` 已经有了，客户端补一条镜像即可。

## 四、待拍板（确认时请挑一下）

> ~~1. 注册放哪？~~ **已定（2026-10-11）：客户端不做注册**，只留「没有账号？去官网注册」链接跳官网。
> 见 §二.4 的理由。

1. **云端文档要不要一个宽窗口？** 本原型是**侧栏单栏树**（契合 236px 侧栏 + 「查找 / 打开」两个动作）。
   如果只是看不删文档，这够了；若要**改名 / 移动 / 删除**（＝服务端 `/account/files` 的能力），
   建议再加一个宽窗口双栏（左树 + 右内容表），侧栏只负责导航。
2. **保存窗口要不要右侧参照列表？** 本原型只给「选目录」；旧客户端还并排一份当前目录内容做参照。
3. **账户页要不要「修改昵称 / 改密码」入口？** 本原型只读 + 提示去官网。
4. **未登录点「云端文档」**：本原型给提示 + 登录按钮（只有「账户」按需求直接弹窗）。是否也改成直接弹窗？
5. **登录窗口形态**：本原型是应用内居中弹窗（与设置等对话框同一套）。若要走真正的独立系统窗口（像旧客户端 `Window`），
   Tauri 侧要多开一个 `WebviewWindow` —— 需要你确认要不要。
6. **登录成功后跳哪？** 本原型自动切到「账户」视图。也可以留在原地只更新状态栏/账户头。

## 五、什么会进产品、什么只是原型脚手架

**结论：底部那条「原型脚手架 · 不随产品发布」控制条不会出现在界面上。** 整页 `cloud-proto.html` 是评审件，
不是产品代码；能被带走的只有下面两样：

| 会被采纳 | 落地方式 |
|---|---|
| 四个界面的**布局与文案** | 重写进 `ui/js/sidebar.js`（`viewAccount` / `viewCloudDocs`）、`ui/js/cloud.js`（两个窗口）、`ui/js/shell.js`（活动栏 + 文件菜单） |
| `cloud-proto.css` 的 **§1–§6** | 并入 `ui/app.css`，类名与变量照抄 |

**明确不进产品的（实施时整段删掉）：**

| 只是一个原型零件 | 在哪 |
|---|---|
| 底部控制条（`已登录 / 未登录`、`已配置 / 未配置`、两个开窗按钮） | `cloud-proto.html` 的 `#proto-ctl`、`cloud-proto.js::renderProtoCtl`、`cloud-proto.css` **§7** |
| 状态栏占位文字「账户 / 云端文档 / 保存到云端 · 原型」 | `cloud-proto.html` 的 `<footer class="statusbar">` |
| 中间欢迎区的说明块 | `cloud-proto.html` 的 `.welcome`（产品里是主原型的欢迎页） |
| `cloud-proto.js` 里的 `DATA`（道荣 / westsource@126.com / 那棵树 / 13 MB） | 实施时换成 `cloud_status`、`cloud_folders`、`cloud_docs_list` 的真实返回 |

控制条存在的唯一理由是评审时**一键切状态**（不用改代码就能看「未登录」「未配置」长什么样）。
评审完不想看到它：点它右端的 `×`，或者用 `?nocontrol=1` 打开 —— 页面上不残留任何痕迹。

## 六、怎么打开 / URL 状态

```
cloud-proto.html                                    账户视图（已登录）
cloud-proto.html?view=cloud                         云端文档视图
cloud-proto.html?view=cloud&filter=mermaid          云端文档筛选
cloud-proto.html?dialog=login                       登录窗口
cloud-proto.html?dialog=login&state=unverified      登录窗口的「邮箱未激活」态（带重发按钮）
cloud-proto.html?dialog=login&state=url             登录窗口的「注册地址可复制」块
cloud-proto.html?dialog=save                        保存到云端窗口
cloud-proto.html?view=cloud&menu=file               文件菜单展开
cloud-proto.html?signed=0                           未登录态
cloud-proto.html?gateway=0                          云网关未配置态
cloud-proto.html?nocontrol=1                        收起底部原型控制条
```

底部居中的**原型控制条**可以即点即切「已登录 / 未登录」「已配置 / 未配置」，并直接打开两个窗口 —— 实施时删除。
