自动配色 · 色系原型（方案 2 + 3）

约定只有一句：模型只写角色，色值由本地按色系落地。理由是实测出来的 —— 同一个提示词两次生成， 模型给的 hex 每次不同；它看不见你的主题，暗色下常写出刺眼的浅底；五种格式的写法还各是一套。 所以「色系」是一个种子色相 + 一条明度梯度，七个角色按固定步长展开（撞上告警红就整体镜像）。 加一种色系 = 加一行数据，不是手抄 42 个 hex。 当前主题：

与 AI 的协作（三个触点）

    

      
触点做什么代价

      
提示词注入「配色只写角色」+ 每种格式可照抄的例子；当前色系名也告诉它每次请求多约 140 字

      
工具 color_scheme只读：列出可用色系与角色。模型想建议换色系时查它，不给"应用"权限按需一步

      
菜单「让 AI 挑」一次短调用，只回 {palette, why}；用户点应用后本地展开一次小请求，失败如实报

    


    
已知边界（不假装支持）

    ① drawio / Excalidraw 没有稳定的节点角色 → 直接拒绝，按钮在这两种格式上整组隐藏；

    ② Mermaid 只有 flowchart 能这么上色（序列图/状态图没有 classDef）→ 报明确错误，不静默失败；

    ③ 色值落进文档后不跟随主题（classDef 里放不了 CSS 变量）→ 按"应用时的主题"选色阶，换主题要再点一次；

    ④ 「整篇重排」会删掉节点上手写的 style（否则它优先级更高、等于没重排）→ 先确认，且默认只做「仅未着色」；

    ⑤ 色相有硬约束：告警红固定在 6°，其余角色 ≤ 32° 就会分不清 → 梯度自己挑方向/槽位。单测钉着，加色系时先跑它。

    配色是渲染期选项：预览/导出按色系上色，正文与磁盘不动 —— 所以打开文件时才能放心
    "检测配色"，且换色系/换主题都是纯视图操作。要把颜色固化给别人看，用菜单里的
    「写入文件」。新建文档默认无；打开没有记过色系的文件时，本地按图里的
    角色占比与标签词挑一个（数据多→黛蓝、异常多→赭石、界面词→藕紫、否则松绿）。
    

    连线也跟色系：线只借主色相的"低饱和、暗一档"（亮色 40% / 暗色 66%），
    不按节点角色染色（那要按边序号写规则，文档一改就错位）；Mermaid 用 init 指令的
    lineColor，所以箭头一起变。
